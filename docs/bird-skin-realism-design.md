# 鸟类羽色真实感优化设计

日期:2026-09-03
范围:`frontend/src/lib/region-engine/world/{BirdFlocks.ts, birdSkins.ts}`

## 1. 问题

- 皮肤 tile 只有 128×96,头部(u < 0.2)仅 ~25 px,颊斑 / 眼纹 / 喙基等鉴别特征画不出来;
- 斑纹以噪声斑块为主("廓羽"细胞随机明暗 + 杂点),鸟看起来是棕色噪点团;
- 翼 / 尾共用一套"叠鳞"区,尾羽画不了黑端带、白斑,肩羽拿覆羽色;腿 / 趾采样覆羽色;
- 麻雀按家麻雀(灰冠)画,而成都平原的"麻雀"是树麻雀(栗冠、白颊黑斑);
- **bug**:鸟数 > 256 时 `tileIdx = fi % maxTiles`,后面的鸟拿到别的鸟种的皮肤。

## 2. 参考

12 种鸟各取英文 Wikipedia 条目首图(均为鉴定级侧面 / 飞行照,Wikimedia Commons)作形态与配色参考:
树麻雀、家燕、原鸽、喜鹊(东方喜鹊)、大嘴乌鸦、绿头鸭(雌雄)、白鹭、银鸥、鸿雁、红隼(雄)、雕鸮、雪鸮(雌)。
只作绘制参考,不采样照片;鉴定要点对照 Cornell / Birds of the World。

## 3. 方案

### 3.1 一致性与个体差异(用户约束)

- 每个**在场鸟种**一个皮肤库:`SKIN_VARIANTS = 8` 张 256×192 tile,由 `(鸟种, 变体号)` 种子绘制;
  同种所有个体只从本种库随机取 tile → 基本纹理一致。
- 个体差异两层:
  1. tile 级(种子):性别(绿头鸭 / 红隼 / 雪鸮)、幼鸟(树麻雀 / 银鸥)、形态型(原鸽 blue-bar / checker / dark / red / pied)、
     斑纹位置密度、羽毛磨损、色相 / 明度抖动;
  2. 实例级(shader,`t7.z/w`):色相偏移 ±、饱和度 0.85–1.15、亮度 0.9–1.08 —— 同一张 tile 的个体也不相同。
- 图集尺寸自适应在场鸟种数(4–6 种 ≈ 4096×384–768),12 种时 4096×1152。

### 3.2 tile 布局(`birdSkins.ts`,几何 UV 同步调整)

- 体区 v ∈ [0, 0.52] 不变(u 喙 → 尾,td 背 → 腹);眼 / 喙钉点位置不变(修正:所有鸟种眼位统一到几何钉点)。
- 翼 / 尾区改为"单片羽"四分区:覆羽 [0.04, 0.34]、**尾羽 [0.36, 0.60](新)**、次级 / 大覆羽 [0.62, 0.83]、初级 [0.84, 0.98];
  羽轴在分区 0.36 处,与 `addFeather` 的 tc = 0.36 对齐;每片画羽轴、羽枝、羽缘、边缘、羽根绒羽。
- **肩羽钉到体区 (0.34, 0.10)**:取背侧体色,喜鹊得到白肩斑。
- **腿 / 趾色块 v > 0.978**:u < 0.5 趾、否则腿(白鹭黑腿黄趾,鸭 / 雁橙腿,鸥粉腿,隼黄腿)。

### 3.3 逐种鉴别特征(节选)

| 种 | 体 | 翼 / 尾 |
|---|---|---|
| 树麻雀 | 栗冠颈背、白颊黑斑、黑颏、白半领、背黑纵纹淡缘 | 覆羽黑心白端(翼斑)、飞羽皮黄缘 |
| 家燕 | 钢蓝上体、锈红额喉、蓝黑胸带、乳白下体 | 尾羽内片白斑 |
| 原鸽 | 深灰头、颈绿紫虹彩、酒灰胸、白腰;五型 | 两道黑翼带(覆羽 / 次级)、尾端黑带、外尾羽白缘 |
| 喜鹊 | 黑头胸背、白腹、白肩斑 | 蓝虹彩覆羽次级、**白初级飞羽黑端**、铜绿长尾紫端 |
| 绿头鸭 | 雄:墨绿头紫晕、白颈环、栗胸、灰体波纹、黑尾覆;雌:鳞斑深眼纹橙喙深鞍 | 蓝紫翼镜双白边;雄白尾 |
| 银鸥 | 白体灰背、冬羽头颈褐纹(个体强度)、喙红点;幼鸟褐鳞斑 | 黑翼尖白斑白端;幼鸟尾带 |
| 鸿雁 | 深栗冠后颈、乳白脸前颈、喙基白线、胁淡横斑、白腹 | 尾白端 |
| 红隼 | 雄:蓝灰头黑髭、栗背黑点、胸纵纹腹点;雌:褐头褐背横斑 | 雄覆羽黑次端点;灰尾黑带白端;雌尾横斑 |
| 雕鸮 | 面盘深缘、背细斑驳、胸粗纵纹、腹细横纹、橙眼 | 飞羽尾羽横斑 |
| 雪鸮 | 雄疏点、雌密横斑,面盘纯白 | 横斑随性别 |

### 3.4 shader

- 高光随鸟种光泽(`morph.w = skinSheen`)增强并偏蓝绿:燕 / 鹊 / 鸦 / 鸽的金属感;
- 逐实例色相 / 饱和度见 3.1。

## 4. 验证

`paintBirdSkin` 为纯 CPU 函数,已离线渲染 12 种 × 3 变体图集 PNG 逐项核对分区对齐与斑纹位置(每 tile ≈ 26 ms,
4–6 种在场时 boot 增加 ≈ 1 s,与旧实现同量级)。场景内渲染效果由使用者自行检查。
